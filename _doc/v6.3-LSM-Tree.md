# v6.3 規劃 - LSM Tree 儲存引擎

## 目標
實現 LSM Tree（Log-Structured Merge-Tree）儲存引擎，提供比 BTree 更強的寫入效能，適合寫入密集的工作負載。

## 為什麼 LSM Tree？

| 特性 | BTree | LSM Tree |
|------|-------|----------|
| 寫入效能 | O(log N) | O(1) (append only) |
| 讀取效能 | O(log N) | O(log N) × level |
| 磁碟空間 | 較小 | 較大 (多重複) |
| 適用場景 | 讀取密集 | 寫入密集 |

## 架構設計

### LSM Tree 層級結構

```
mem_table (記憶體)          ← 活躍寫入
    ↓ flush
L0 (sstable)              ← 第一層磁碟
    ↓ merge
L1 (sstable)              ← 第二層
    ↓ merge
L2 (sstable)              ← 第三層
    ...
```

### 核心元件

```rust
struct LsmStorage {
    mem_table: BTreeMap<Key, Value>,    // 記憶體表（活躍寫入）
    l0_tables: Vec<SSTable>,            // L0 層（磁碟）
    l1_tables: Vec<SSTable>,            // L1 層
    // ...
}

/// SSTable: Sorted String Table
struct SSTable {
    file_id: u64,
    data_path: PathBuf,
    index_path: PathBuf,
    bloom_path: PathBuf,
    min_key: Vec<u8>,
    max_key: Vec<u8>,
    size_bytes: u64,
}
```

## 與現有模組整合

```rust
// 在 Storage trait 中新增
pub enum StorageType {
    BTree,
    Lsm,
    Memory,
}

// 建立工廠
impl Storage {
    pub fn open_with_type(path: &Path, storage_type: StorageType) -> Result<Box<dyn Storage>> {
        match storage_type {
            StorageType::BTree => Ok(Box::new(DiskStorage::open(path)?)),
            StorageType::Lsm => Ok(Box::new(LsmStorage::open(path)?)),
            StorageType::Memory => Ok(Box::new(MemoryStorage::new())),
        }
    }
}
```
