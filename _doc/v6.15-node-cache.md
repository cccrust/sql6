# v6.15 - Node 快取與 Lock Striping

## 日期
2026-05-15

## 主要功能

### 1. Node 層級快取
- 快取解碼後的 `Node` 物件
- 避免重複解碼相同頁面
- LRU 淘汰策略，記憶體上限控制

### 2. Lock Striping（鎖區段化）
- 擴展鎖池，減少高並發時的鎖競爭
- 動態調整鎖區段數量
- 降低讀取單一頁面的延遲

### 3. Write Coalescing（寫入合併）
- WAL 批次寫入合併，減少 fsync 次數
- 合併時間窗口（可配置）
- 寫入吞吐量提升

## 實現狀態

### Phase 1: Node Cache
- [ ] NodeCache 結構（解碼後的 Node）
- [ ] get_node() / put_node() API
- [ ] LRU 淘汰（max_nodes 限制）
- [ ] write_node() 時 invalidate
- [ ] DirStorage 整合 node_cache

### Phase 2: Lock Striping
- [ ] StripeLockManager 結構
- [ ] 動態鎖區段數（預設 64 區段）
- [ ] 映射 page_id → stripe
- [ ] 減少讀取熱門頁面的競爭

### Phase 3: Write Coalescing
- [ ] 寫入緩衝區（pending_writes）
- [ ] 定時 flush 或 threshold 觸發
- [ ] 合併同一頁面的多次寫入

## 技術細節

### NodeCache 配置
```rust
pub struct NodeCache {
    nodes: RwLock<HashMap<usize, (Node, Instant)>>,
    max_nodes: usize,
}

impl NodeCache {
    pub fn get(&self, page_id: usize) -> Option<Node> { ... }
    pub fn put(&self, page_id: usize, node: Node) { ... }
    pub fn invalidate(&self, page_id: usize) { ... }
}
```

### StripeLockManager 配置
- 預設 64 區段
- page_id → stripe = page_id % num_stripes
- 每區段獨立的 RwLock

### Write Coalescing 配置
- 合併窗口: 5ms
- 閾值: 100 個待寫入頁面
- 最大合併: 1024 頁面/批次

## 效能提升
- Node 重複讀取: 解碼 CPU 降低 50%+
- 熱門頁面讀取: 鎖競爭降低 80%+
- 寫入吞吐量: fsync 次數減少 70%+

## 影響範圍
- `DirStorage` - 主要受益者
- `FileBTreeStorage` - 可考慮相同優化
- 其他模組無變化
